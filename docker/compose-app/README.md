# Схема сервисов

В проекте есть три основные части:

- **frontend** — клиентская часть приложения. Отдаёт пользователю страницы, интерфейс и статику.
- **backend** — серверная часть приложения. Обрабатывает запросы, бизнес-логику и отдаёт данные.
- **nginx** — reverse proxy. Принимает внешние HTTP-запросы и перенапляет их к нужному сервису внутри Docker-сети.

## Как устроено взаимодействие

Пользователь снаружи обращается только к **nginx**.

Дальше nginx сам решает, куда отправить запрос:

- запросы к frontend направляются во **frontend**
- API-запросы направляются в **backend**

Пример общей схемы:

```text
User → nginx → frontend
User → nginx → backend
```

## Кто к кому ходит

Пользователь не обращается напрямую ни к frontend, ни к backend.

Внешний путь такой:

```text
User → nginx
```

Внутри Docker-сети nginx ходит к нужным сервисам:

```text
nginx → frontend
nginx → backend
```

То есть **nginx** является единой точкой входа, а **frontend** и **backend** остаются внутренними сервисами.

## Почему наружу открыт только nginx

Наружу открыт только **nginx**, потому что именно он принимает все внешние запросы.

Это нужно, чтобы:

- не открывать лишние порты наружу
- скрыть frontend и backend внутри Docker-сети
- управлять маршрутизацией в одном месте
- сделать вход в приложение проще и безопаснее

Frontend и backend доступны для nginx внутри Docker-сети, но напрямую снаружи к ним обращаться не нужно.

## Где frontend, backend и reverse proxy

- **frontend** — сервис с пользовательским интерфейсом
- **backend** — сервис с API и серверной логикой
- **nginx** — reverse proxy, который стоит между пользователем и внутренними сервисами
